## `blogs/` 目录说明（架构镜像）

### 1. 目录定位

- **目标**：集中管理面向外部受众（.NET × AI）的博客内容与写作计划，确保文章结构可持续演进、可复用、可审计。
- **原则**：内容从“愿景→心智模型→上手→生产化”逐层深入，并与仓库 `docs/`、`examples/` 保持强绑定（读者可复现）。

---

### 2. 目录结构

```text
blogs/
  PLAN.md              # 博客系列写作计划（文章路线图、规范、素材清单）
  docs/
    README.md          # 本文件：目录用途、结构与约定（防止“架构失忆”）
```

---

### 3. 内容约定（与仓库规则对齐）

- **Protobuf 铁律**：任何跨边界类型（State/Event/Config/ES Event）必须 Protobuf。
- **端口约束**：文档/示例/默认配置不要使用 5000 端口；需要默认端口时优先 `:5678`。
- **可复现优先**：每篇文章应绑定一个可运行入口（`examples/` 或 `apps/`），并明确命令与预期输出。
