## Artifacts

### API Endpoints

#### POST /api/sessions
- **Purpose:** Create a session and eagerly initialize file-backed workspace (workspace tree + paper scaffold).
- **Location:** scientific-research-assistant/src/ScientificResearchAssistant.Api/Sessions/ResearchSessionsApi.cs
- **Request Format:** { providerName?: string }
- **Response Format:** { ok: true, sessionId: string }

#### POST /api/sessions/{sessionId}/facts
- **Purpose:** Create a new fact proposal under workspace facts_proposed/ (does NOT write directly into facts/).
- **Location:** scientific-research-assistant/src/ScientificResearchAssistant.Api/Sessions/ResearchSessionsApi.cs
- **Request Format:** { title?: string, content: string, evidencePaths?: string[] } (requires Materials:AllowWrite=true)
- **Response Format:** { ok: true, sessionId: string, proposal: { factId: string, title: string } }

#### GET /api/sessions/{sessionId}/workspace
- **Purpose:** Return bounded workspace snapshot derived from files (facts/facts_proposed/sources counts + recent proposed files).
- **Location:** scientific-research-assistant/src/ScientificResearchAssistant.Api/Sessions/ResearchSessionsApi.cs
- **Request Format:** (none)
- **Response Format:** { ok: true, sessionId: string, workspace: WorkspaceScanResult }

#### POST /api/sessions/{sessionId}/facts/{factId}/votes
- **Purpose:** Record a reviewer vote for a proposed fact (decisions/votes).
- **Location:** scientific-research-assistant/src/ScientificResearchAssistant.Api/Sessions/ResearchSessionsApi.cs
- **Request Format:** { reviewerId: string, vote: 'approve'|'reject'|'needs_work', comment?: string }
- **Response Format:** { ok: true, sessionId: string, factId: string }

#### POST /api/sessions/{sessionId}/facts/{factId}/verifications
- **Purpose:** Record a verification result for a proposed fact (decisions/verifications).
- **Location:** scientific-research-assistant/src/ScientificResearchAssistant.Api/Sessions/ResearchSessionsApi.cs
- **Request Format:** { verifierId: string, tool?: string, result: boolean, artifactPaths?: string[], logExcerpt?: string }
- **Response Format:** { ok: true, sessionId: string, factId: string }

#### POST /api/sessions/{sessionId}/facts/{factId}/promote
- **Purpose:** Evaluate current votes/verifications and (if criteria met) write final decision and promote to facts/.
- **Location:** scientific-research-assistant/src/ScientificResearchAssistant.Api/Sessions/ResearchSessionsApi.cs
- **Request Format:** { finalizedBy?: string }
- **Response Format:** { ok: true, sessionId: string, factId: string, pending?: true } OR { ok: true, decision: string, basis: string, rationale: string }

### Integrations

#### Integration
- **Description:** HTTP endpoints drive file-backed state transitions (facts_proposed + decisions + promote) and provide bounded snapshots for UI; session creation initializes workspace tree so later agents can operate purely on files.
- **Frontend Component:** frontend session UI + workspace modal (existing)
- **Backend Endpoint:** POST /api/sessions, POST /api/sessions/{id}/facts, GET /api/sessions/{id}/workspace, POST /votes|/verifications|/promote
- **Data Flow:** Client creates session -> server creates workspace dirs + paper files -> client proposes fact -> written to facts_proposed -> reviewers/verifiers post updates -> promote endpoint finalizes + writes into facts/ -> workspace endpoint/AG-UI can project current state.
